## F-103: the README carried two numbers no check could see

The last thing this feature did was read `README.md` closely, and it was carrying
**98 findings** (really 102) and **105 deliberate corruptions** (really 113).

`AGENTS.md` and `blueprint/context/project-overview.md` are both checked against
the findings ledger. The README states the same total in prose and **was not on
the list** — the one document a judge is most likely to read, protected by
nothing.

**This is F-57's class, one document further along**, and it is the third instance
of the same shape in this project: a tally enforced in the places someone
remembered rather than the places that needed it. The generalisation is the part
worth carrying forward:

> A fact printed in N places needs N checks, or one check that finds all N.

Three checks now derive both numbers rather than trusting them:

- the findings total comes from the ledger, the same source the other two files use;
- the mutation count is obtained by **parsing `mutation_test.py`'s own `MUTATIONS`
  list**, not by importing it — importing the harness would run its module body;
- and a fourth assertion checks the parse found entries **at all**, so a regex
  that stops matching reports a *failure* rather than a smaller number. A count
  that silently shrinks is the F-57 shape wearing a check's clothes.

**The new check caught real drift within one commit of being written.** Adding
F-103 itself moved the total to 103, and all three files still said 102. That is
the check working on its first live change rather than being decorative.
